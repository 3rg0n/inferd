fresh-machine installer → `inferdctl doctor` reports `ready` → real
`generate` + `embed` + the OpenAI-compat bridge, from the **release
tarball** (no mock, no hand-edited config, no dev build).

  (≥ `model_autoselect_min_vram_gib`, default 20 → 12B, else E4B).

  (`image_url` → RGB attachment) — bundled in every tarball.
- Windows arm64 is **parked** this line (task #185 — b9850 load crash).

## Feature gates (per platform, real model, from the installed tarball)

Run against the installed daemon on `\\.\pipe\inferd` (Win) / UDS
(Linux) — no mock, no dev build, no `cargo` test daemon.

### G1 — baseline text
- ☑ Windows x64 CUDA (2026-07-12): "capital of France, one word" →
  `text="Paris"`. First request 65 s (one-time model load / CUDA warmup);
  warm requests instant.

### G2 — thinking activation, no channel-token leak
- ☑ Windows x64 CUDA (2026-07-12): "6×7, give the number", `thinking:true`,
  budget 256 → answer `text="42"`, reasoning on the separated `thinking`
  channel, **no `<|channel|>`/`<|start|>`/"channel" markers leaked into
  user-visible text**. ~144 tok/s (full GPU offload; CPU would be ~5).

### G3 — structured output (grammar)
- ☑ Windows x64 CUDA (2026-07-12): JSON-Schema `response_format`
  {capital, population_millions} → `{"capital":"Paris",
  "population_millions":68}` — parses, conforms to schema.

### G4 — vision / OCR round-trip (raw-BLOB attachment)
- ☑ Windows x64 CUDA (2026-07-12): 768×420 known-text PNG → decoded to raw
  RGB → BLOB attachment → `input_tokens=165` → transcribed
  `"INFERD V0.6 OCR / token: TOPAZ-9021 / status: VALIDATED"` (both known
  strings recovered).

### G5 — inferd-http bridge from the tarball (new in 0.6)
The bundled `inferd-http` launched against the installed daemon,
driven by the **real `openai` Python SDK** (base_url `/v1`):
- ☑ Windows x64 CUDA (2026-07-12): chat non-stream ("Paris"), chat stream
  ("Tokyo"), embeddings (768-dim), and **vision** (`image_url` data URL →
  transcribed TOPAZ-9021 + VALIDATED) — all pass. `/health` open, `/v1/*`
  served. Bridge is the tarball binary, not a dev build.
- ☑ Linux x64 CUDA / WSL (2026-07-12): same via the bundled Linux
  `inferd-http` (reached from the Windows-side SDK over WSL's localhost
  mirror) — chat, stream, embeddings (768), vision all pass.

### ⚠️ Bridge gap found during validation — structured output not mapped
The `inferd-http` bridge does **not** forward OpenAI `response_format`
(JSON-schema structured output): `ChatRequest` in `inferd-openai-wire`
has no `response_format` field and `chat_request_to_v2` never sets
`RequestV2.response_format`, so an OpenAI client requesting a JSON schema
**silently gets unconstrained text**. The daemon fully supports grammar
(G3 passes natively — Windows above) and the wire has the field; only the
bridge's OpenAI-surface mapping is missing. Not a crash; a missing
capability on the bridge. Tracked for a follow-up — decide whether GA
ships the bridge with this gap documented or with the mapping added.

## Model auto-selection (ADR 0023)
- ☑ Windows x64 CUDA (2026-07-12): 16 GB total VRAM (< 20 GiB threshold) →
  auto-select correctly warms **E4B** (log: `warming gemma-4-e4b …
  total_vram≈17 GB free≈15.7 GB, embed on accelerator`).
- ☐ **12B tier UNVALIDATED**: needs a ≥ 20 GiB accelerator; no such box
  available here. The 12B path has never loaded a real model. GA note.
