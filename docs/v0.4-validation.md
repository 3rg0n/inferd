# v0.4 install=work + wire validation

v0.4.0 is **not** releasable until both gates below are green from a
fresh-machine run — no mock backend, no hand-edited config, no
`inferdctl pull` precondition. Run from the release tarball the GitHub
Actions release workflow produces for the matching target triple, **not**
from `cargo build`.

v0.4 carries two distinct risks, so it has two gates:

1. **install=work** — the same fresh-machine → real generate + real
   embed loop v0.3 gated (the accelerator-detection machinery of
   ADR 0019 is unchanged). Re-validated because the wire change touches
   every client path.
2. **wire format** — the v0.4 change ([ADR 0021](adr/0021-unified-v2-wire-length-prefixed-blob-framing.md)):
   one generation socket on a neutral path, length-prefixed type-tagged
   framing, raw BLOB media, in-band `wire_version`. This is the
   load-bearing new surface and must be proven end-to-end against a real
   model, not just in unit tests.

If any step fails, **don't fix in place** — record the failure, file an
issue, and do not cut the release.

## Gate 1 — install=work coverage matrix

Tarballs ship from `.github/workflows/release.yml`. Every shipped target
must be exercised on hardware that can load the matching backend MODULE.
The per-platform procedure is identical to
[`docs/v0.3-validation.md`](v0.3-validation.md) §"Per-platform procedure"
— extract tarball → run install script → `inferdctl doctor` reports the
expected `accelerator=` + `device:` → real generate (≥4 tokens, no
`error` frame) → real embed (vectors, no `error` frame). The only
v0.4 difference in that loop: `inferdctl doctor` now prints
`wire_version=1` on the capabilities line, and the generation socket is
`inferd.sock` / `\\.\pipe\inferd` (not `infer.sock` / `infer.v2.sock`).

## Gate 2 — wire-format end-to-end

The framing redesign must be proven through the *full* pipeline: a real
client emits a length-prefixed request frame (+ BlobDescriptor + BLOB
frames for media), the daemon enforces the `wire_version` gate,
reassembles BLOBs by id, and streams length-prefixed response frames
back. Unit/integration tests cover the codec; this gate proves it
against a real model on real hardware.

### W1 — automated cross-language round-trip (per PR, every platform)

`clients/go` `TestEndToEndAgainstDaemon` launches the freshly-built
daemon (mock backend, TCP) and round-trips `GenerateV2` over the
length-prefixed wire. This is the load-bearing cross-language stability
check — it exercises the Go frame codec + `wire_version` against the
Rust daemon with no GPU needed.

- Command: `cargo build -p inferd-daemon && (cd clients/go && go test ./...)`
- Status: ☑ green on Windows x86_64 (this box, 2026-06-13) — also runs in CI.

### W2 — `wire_version` mismatch fails loudly

Send a generation request with a `wire_version` the daemon doesn't speak
(e.g. `0` or `99`); the daemon must reply with a single
`error{code:"wire_version_unsupported"}` frame and close — never parse
the body, never hang.

- Covered by the `unsupported_wire_version_errors_and_closes`
  integration test (`crates/inferd-daemon/tests/v2_stub.rs`): drives a
  bad `wire_version` through the socket and asserts a single
  `Error{WireVersionUnsupported}` frame followed by EOF.
- Status: ☑ automated (Windows x86_64, 2026-06-16; runs in CI).

### W3 — real-model text round-trip (per accelerator that ships)

A real `GenerateV2` text request through a release-tarball daemon with
the default `gemma-4-e4b` backend returns a coherent answer, terminating
with a `done` frame carrying `backend:"llamacpp"` and `stop_reason`.

- Status: ☑ Windows x86_64 CPU (this box, 2026-06-16): real-model text
  through a v0.4 llamacpp daemon over the LP wire, clean `done` with
  `backend:"llamacpp"`. (`tests/echo_llamacpp.rs`, `llamacpp-integration`
  feature, gemma-4-e4b.) This run uncovered + fixed two v1→v2-fold
  regressions — see CHANGELOG "Fixed".
- Status: ☑ Linux x86_64 CPU via WSL Ubuntu (this box, 2026-06-16):
  same `echo_llamacpp` real-model text e2e over the LP wire, green
  (33.7s incl. model load).
- Status: ☑ macOS arm64 Metal (Apple M1, 2026-06-17): `GenerateV2` over
  `${TMPDIR}/inferd/inferd.sock` (LP wire) → `answer="Four"`,
  `backend=llamacpp`, `stop=end_turn`. `go test ./...` (15 tests, 2
  linux-skipped) + `inferdctl doctor` (wire_version=1, accelerator=metal,
  device=MTL0 vram=11.8 GiB) both clean. Two macOS-only test
  regressions found and fixed: `defaultDaemonBin` now prefers
  `target/release` over stale `target/debug`, and test daemon gets HOME
  isolation. (commit 87793c0)

### W4 — raw-BLOB multimodal round-trip (per vision-capable target)

A `GenerateV2` request carrying an image as a **raw BLOB frame** (not
base64) — image content block + matching attachment + BlobDescriptor +
BLOB frame — reaches mtmd and produces a grounded answer. Proves BLOB
reassembly-by-id and the no-base64 media path end-to-end.

- Status: ☑ Windows x86_64 CPU (this box): the v2 image-attachment
  round-trip through mtmd (`tests/llamacpp_multimodal.rs`
  `v2_image_attachment_round_trips`, gemma-4-e4b + mmproj) — the
  attachment's raw bytes reach mtmd via the BLOB path, no base64. Earlier
  (2026-06-13) a 256×256 image sent as one BLOB frame through the daemon
  answered *"A solid red circle is centered on a white background."*
  (in=276, ~250 vision tokens).
- Status: ☑ Linux x86_64 CPU via WSL Ubuntu (this box, 2026-06-16):
  `llamacpp_multimodal` v2 image-attachment round-trip green (2 passed,
  33.8s).
- Status: ☐ macOS arm64 Metal — requires mmproj build; W4 BLOB wire
  encoding verified by mock tests (`TestGenerateV2WithBLOBAttachment`,
  `v2_stub.rs` multimodal attach tests).

## Release checklist

Before tagging v0.4.0, confirm with the user (no tags without
confirmation), then:

- [ ] Every non-skip row in Gate 1 is ☑ from a release-tarball run.
- [ ] W1 green in CI on every platform.
- [ ] W2 manual spot-check ☑ on at least one release tarball.
- [ ] W3 ☑ on every shipped accelerator target.
- [ ] W4 ☑ on every vision-capable target (CPU counts — vision works on
      CPU, just slower).
- [ ] `CHANGELOG.md` `[Unreleased]` rolled to `[0.4.0]` with the date.
- [ ] Workspace version bumped `0.4.0-dev` → `0.4.0`.

ADR 0021 is already `accepted`; no status flip needed at release.
